# PRP — P1.M3.T1.S1: Add @deprecated JSDoc to the dead checkpoint agent-tool surface (zero behavior change)

## Goal

**Feature Goal**: Mark the unregistered checkpoint agent-tool surface in `src/tools/checkpoint.ts` as `@deprecated` via JSDoc so no one re-wires it as an agent tool, without deleting, renaming, or altering any behavior.

**Deliverable**: `@deprecated` JSDoc blocks added to exactly four exports in `src/tools/checkpoint.ts`: `makeCheckpointTool`, `CKPT_DESC`, `CheckpointParams`, `CheckpointDetails`. Nothing else.

**Success Definition**: `npx tsc --noEmit` clean, `npm test` fully green with **zero test edits**, and `src/commands.ts` / `test/integration/smoke.ts` / `test/edge-cases.test.ts` consume the module unchanged.

## Why

- PRD recommendation #4 (bug_validation.md §Recommendations): "Consider deleting or clearly deprecating the now-unregistered src/tools/checkpoint.ts agent-tool module to prevent future re-wiring confusion."
- The module **must NOT be deleted** — it still contains live shared logic: `validCheckpointName` (line ~74) is imported by `src/commands.ts:34` and used at `src/commands.ts:172` by the `/mulligan_checkpoint` slash command, and `makeCheckpointTool` is driven by the integration smoke harness (`test/integration/smoke.ts:286,302`) plus unit tests (`test/edge-cases.test.ts:47,670,809`).
- v1.1 removed the agent-callable checkpoint tool (spec/05 §3 / E23: "There is no agent-callable way to create a checkpoint"); `src/index.ts:53-56` registers only 4 tools (`mulligan_rewind`, `mulligan_shrink`, `mulligan_audit`, `mulligan_cancel`).

## What

Add a `@deprecated` JSDoc tag + explanation to the doc blocks of:

1. **`makeCheckpointTool`** (line ~182)
2. **`CKPT_DESC`** (line ~84)
3. **`CheckpointParams`** (line ~53)
4. **`CheckpointDetails`** (line ~91)

Each deprecated block states (adapted to the symbol):
> `@deprecated` Removed as an agent tool in v1.1 (spec/05 §3 / E23 — checkpoint creation is human-only via the `/mulligan_checkpoint` command). Only `validCheckpointName` remains live shared logic (consumed by src/commands.ts). `makeCheckpointTool` survives solely as the integration harness's deterministic label-setter (test/integration/smoke.ts).

**DO NOT annotate**: `validCheckpointName` (live), `CheckpointArgs` (the Static<> type of the deprecated schema — optional; annotating it is fine but not required; leave it to avoid churn), `refusal` (module-private, part of the deprecated surface but private — optional), `checkpointExecute` (private).
